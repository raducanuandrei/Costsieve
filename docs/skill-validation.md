# CostSieve audit skill validation, 1 November 2026

The skill is original repository material. These checks validate packaging, calculations, instructions and fictional behavior; they do not establish live compatibility with every AI provider or accounting connector.

## Functional checks

- Engine handoff tests: private marker exclusion across IDs/descriptions/caveats, opt-in names, missing revenue, negative scenario effect, demo origin, partial coverage, currency rejection and bounded detail previews.
- MCP tests: actual connected CSV preparation/review/completion, exact totals, UTF-8 size validation, unchanged approved-root restrictions and a real SDK stdio client with a CSV larger than 1 MiB.
- Package check: exactly four public source/license entries, byte-for-byte source integrity, valid required skill metadata and a literal skill invocation in optional client UI metadata. No report, secret or generated business data enters the archive.
- Website check: exact preview/copy/download equivalence, explicit report confirmation, confirmation reset, dirty-state blocking, currency mismatch disclosure, generic use without a report, clipboard denial fallback and real archive download. Network observation permits only local static GETs.

## Fictional agent evaluations

A baseline agent received a fictional tool catalog and evidence about a prepaid annual service, ten minimum committed seats with four active, a superficially cheaper alternative, duplicate invoice/payment evidence, an unmatched refund and revenue. It identified several financial constraints safely, but could not feed connected records into the original local-path-only CostSieve preparation interface. This motivated the explicit in-memory connector representation bridge; the baseline is not evidence that an unskilled assistant always fails financially.

A separate agent read the completed skill and MCP reference and examined the same case plus a variation without web access or revenue. It discovered the supplied read-only tools, planned the canonical CSV bridge, retained minimum-seat and commitment constraints, distinguished annual cash from monthly comparison, kept the refund unallocated, rejected malicious embedded instructions and asked directly about missing ISO currency, dates and operational context. It did not claim fictional tool calls were executed. With unavailable browsing/revenue it disclosed gaps instead of inventing alternatives, prices or profit.

These were simulated scenarios, not real account connections, live pricing/legal verification, achieved savings, accuracy benchmarks or a guarantee that another model follows every instruction. Provider permissions, model behavior and connector schemas must be checked in the actual host.

## Independent review

A fresh read-only whole-change review ran the new engine, package and MCP tests (9/9 passing) and found no critical or important issues. A minor wording finding clarified that the names opt-in may include revenue counterparties/customers as well as vendors and categories. The interface and documentation now say so explicitly.
